# Prototype (v3): The Build That Tests the Hypothesis

> Module 2 · Validation. The prototype is a hypothesis test, not a demo.

## Link

https://trust-builder-prototype.lovable.app

## What it tests

_Tie it back to the validation brief: which assumption does this prototype put in front of a user?_

Buyers won't book a brand-new, zero-review provider whatever the price.

## Context injected (no placeholders)

- **Real user quotes on screen:** “If there are no reviews, I assume something's wrong with them. I'll pay more for someone with a track record.” / “I'm great at my job but I'll never get a review if no one books me first. It's a chicken-and-egg trap.”
- **Domain metrics on screen:** 0 Reviews on 41% of active provider profiles. / 2.3% Booking rate for zero-review providers vs. 14% for reviewed. / 68% Search → profile → exit without booking.

## Iteration log (v1 → v3)

| Version | Change | Why |
|---|---|---|
| v1 | Create first provider's overview | Increase buyers' trust in the provider. |
| v2 | Interaction with the prototype | Make the prototype feel like a real product rather than just a visual mockup. |
| v3 | More detailed provider and product information and additional capabilities | Increase trust in both the product and the provider, reduce the median time to first booking for new providers, and increase the booking rate. |
